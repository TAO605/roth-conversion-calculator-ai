# V1.3 Engineering Addendum - Homepage Performance Boundaries

Date: 2026-05-30

This addendum records the next homepage performance step after adding richer result actions and review workflows.

## Implemented

- Converted `CalculatorAnalyticsBeacon` from a static homepage import to a dynamic client-only import.
- Kept analytics browser-only with `ssr: false` because it only sends delayed GA events.
- Added stable-height lazy fallbacks for the projection chart and AI helper to reduce layout shift risk while chunks load.
- Extended homepage performance tests to guard dynamic imports and fallback sizing.

## SEO / Core Web Vitals Rationale

- The calculator and primary result area should remain the first interactive product surface.
- Tracking and below-the-fold explanation modules should not compete with first-load rendering.
- Reserving approximate loading heights helps prevent content jumps when lazy modules hydrate.

## Validation Targets

- `tests/core/homepage-performance.test.ts`
- Full `npm test`
- `npm run build`
- Desktop and mobile browser smoke for action visibility and horizontal overflow
- Live homepage and sitemap checks after deployment
