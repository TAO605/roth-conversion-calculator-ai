# V1.3 Engineering Addendum - Homepage Performance Boundaries

Date: 2026-05-30

This addendum records the next homepage performance step after adding richer result actions and review workflows.

## Implemented

- Converted `CalculatorAnalyticsBeacon` from a static homepage import to a dynamic client-only import.
- Kept analytics browser-only with `ssr: false` because it only sends delayed GA events.
- Added stable-height lazy fallbacks for the projection chart and AI helper to reduce layout shift risk while chunks load.
- Extended homepage performance tests to guard dynamic imports and fallback sizing.

## SEO / Core Web Vitals Rationale

- The calculator and primary result area should remain the first interactive product surface.
- Tracking and below-the-fold explanation modules should not compete with first-load rendering.
- Reserving approximate loading heights helps prevent content jumps when lazy modules hydrate.

## Validation Targets

- `tests/core/homepage-performance.test.ts`
- Full `npm test`
- `npm run build`
- Desktop and mobile browser smoke for action visibility and horizontal overflow
- Live homepage and sitemap checks after deployment

## PageSpeed Mobile Evidence Loop

The PageSpeed Insights URL shared on 2026-06-02 showed that field data is not yet available for this young property, so mobile performance work must rely on repeatable lab evidence until Search Console and CrUX accumulate enough real-user samples.

Current project guard:

- `npm run seo:performance` runs mobile Lighthouse against `https://www.roth-conversion-calculator-ai.shop`.
- The command records `performance-evidence-result.json` with performance score, SEO score, LCP, TBT, CLS, Lighthouse version, final URL, and threshold metadata.
- The SEO Smoke workflow uploads the file inside the retained `production-seo-evidence` artifact.
- `npm run seo:evidence-validate` blocks the artifact if mobile Lighthouse falls below the current guardrail.

Current conservative thresholds:

- Mobile Lighthouse performance score: at least `0.75`.
- Mobile Lighthouse SEO score: at least `0.95`.
- Largest Contentful Paint: at most `5000ms`.
- Total Blocking Time: at most `300ms`.
- Cumulative Layout Shift: at most `0.1`.

Baseline captured locally on 2026-06-02:

- Mobile performance score: about `0.82`.
- SEO score: `1.00`.
- LCP: about `4127ms`.
- TBT: about `98ms`.
- CLS: `0`.

Next optimization target:

- Reduce mobile LCP before tightening the threshold below `5000ms`.
- Keep YMYL copy, schema, and calculator behavior unchanged while optimizing render path.
