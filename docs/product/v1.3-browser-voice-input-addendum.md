# V1.3 Browser Voice Input Addendum

This addendum closes the safest practical part of the V2 voice-input idea without adding native Siri integration, server audio processing, account storage, or AI interpretation.

## Implemented

- Added `VoiceInputAssist` behind the `voice-input-assist` feature flag.
- Uses browser speech recognition only when `SpeechRecognition` or `webkitSpeechRecognition` exists.
- Checks browser microphone permission and requests one-time microphone access before starting speech recognition.
- Shows a clear blocked-permission message when the browser returns `not-allowed`, instead of leaving the button feeling unresponsive.
- Supports bounded numeric field phrases such as:
  - `conversion amount 50000`
  - `current taxable income 85000`
  - `state tax rate 5`
  - `traditional IRA balance 250000`
- Applies a matched value through the same calculator state path as manual input.
- Shows an explicit review message after applying a voice value.

## Boundaries

The feature does not:

- Send audio to this website.
- Store voice transcripts.
- Call paid AI models.
- Interpret tax advice or personal recommendations.
- Claim native Siri shortcut support.
- Add unsupported voice claims to structured data.

Manual input remains the primary and complete input method.

## Acceptance Evidence

- `parseVoiceInputCommand()` is unit tested for supported phrases, percent conversion, unknown phrases, and negative values.
- Microphone permission denial is unit tested so the UI shows an actionable blocked state.
- `VoiceInputAssist` is rendered only through `isFeatureEnabled("voice-input-assist")`.
- The feature registry tracks a rollback path that preserves all manual inputs.
