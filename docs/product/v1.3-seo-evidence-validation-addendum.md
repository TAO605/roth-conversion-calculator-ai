# V1.3 SEO Evidence Validation Addendum

Date: 2026-05-30

## Purpose

This addendum closes the evidence-artifact loop. The SEO Smoke workflow already uploads `production-seo-evidence`; this step makes the artifact itself a checked contract before upload, so future Search Console retry work and incident review can trust the saved JSON files.

## Implemented Scope

- Added `scripts/validate-seo-evidence.mjs`.
- Added `npm run seo:evidence-validate`.
- Added a `Validate SEO evidence artifact` step before `actions/upload-artifact`.
- Added `seo-evidence-validation-result.json` to the uploaded artifact so the validation summary is retained with the evidence files.
- Added `seo-evidence-manifest.json` to the uploaded artifact so run metadata, commit identity, event type, file list, file sizes, and retention window are retained with the proof package.
- Updated the manifest to list itself as a self-describing generated file so the artifact inventory covers all retained JSON files.
- Added a visible `/seo-monitoring` artifact review checklist so downloaded proof packages are checked for smoke status, GSC priority URL evidence, validator summary, and manifest traceability before Search Console retries or incident notes.
- Added tests that keep workflow output filenames aligned with validator defaults.
- Made the validator tolerate UTF-8 and PowerShell UTF-16LE JSON files for local artifact review.
- Added `scripts/blog-discovery-evidence.mjs` and retained `blog-discovery-evidence-result.json` so blog publication discovery is checked in the same evidence artifact.

## Validated Files

The validator reads:

- `seo-smoke-result.json`
- `gsc-evidence-result.json`
- `structured-data-evidence-result.json`
- `blog-discovery-evidence-result.json`

The workflow also retains:

- `seo-evidence-validation-result.json`
- `seo-evidence-manifest.json`

## Checks

The validator confirms:

- Both files are parseable JSON objects.
- Both evidence files use the same canonical production host.
- SEO smoke evidence has `ok: true`.
- Homepage, robots, sitemap, and llms checks return HTTP `200`.
- GSC evidence has `ok: true`.
- Priority URLs are present, return HTTP `200`, appear in sitemap, do not send `noindex`, and expose canonical URLs on the expected host.
- Freshness-critical priority URLs return `lastmodFresh: true`.
- Structured-data evidence covers the homepage, monitored educational pages, and current blog Article pages.
- Blog discovery evidence confirms every current blog post appears in the blog hub, sitemap, and RSS feed, while `llms.txt` covers the expected recent guide subset.

## Operating Rule

If artifact validation fails in CI, treat the failure as an evidence-contract problem. Inspect the failing field before retrying Search Console request-indexing or using the artifact for incident review.

## Downloaded Artifact Review

Before using a `production-seo-evidence` artifact for sitemap resubmission, URL Inspection, indexing incident review, or recovery notes:

- Check `seo-smoke-result.json` for `ok: true` and production host consistency.
- Check `gsc-evidence-result.json` for priority URL HTTP `200`, canonical host, sitemap inclusion, no `noindex`, and required `lastmodFresh: true`.
- Check `structured-data-evidence-result.json` for required JSON-LD types, canonical host consistency, and zero forbidden keys/text.
- Check `blog-discovery-evidence-result.json` for full blog hub, sitemap, and RSS coverage before publishing or submitting new article URLs.
- Check `seo-evidence-validation-result.json` for `ok: true` so the retained evidence files are known to satisfy the artifact contract.
- Check `seo-evidence-manifest.json` for `artifactName`, `gitHubRunId`, `gitHubSha`, `retentionDays`, retained files, and the manifest self-entry with `selfDescribing: true`.
