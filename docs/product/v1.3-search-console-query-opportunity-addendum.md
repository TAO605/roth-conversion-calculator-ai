# V1.3 Search Console Query Opportunity Addendum

Date: 2026-05-30

## Purpose

This addendum extends the V1.3 engineering manual with a safer SEO growth loop: Search Console queries should become review-gated content actions, not unchecked keyword pages.

## Implemented Scope

- Added `buildSearchConsoleOpportunityMatrix()` in `src/content/seo-monitoring.ts`.
- Rendered the matrix on `/seo-monitoring` after the Search Console submission loop.
- Added `npm run seo:gsc-query-opportunity-import` to convert user-provided Google Search Console Performance CSV exports into review-gated query opportunity records when logged-in browser control is unavailable.
- Covered six query clusters:
  - Core calculator intent
  - Bracket room questions
  - Hidden tax interaction questions
  - Payment and withholding questions
  - State and filing-status questions
  - Process, forms, and CPA handoff questions
- Each cluster includes example queries, user intent, target surface, action, review gate, and risk level.

## SEO Operating Rule

Use actual GSC queries to decide whether the next action is:

- homepage/result copy refinement,
- internal link improvement,
- existing guide refresh,
- new educational page,
- professional-review issue before formula or tax-data changes.

Do not publish one thin page per keyword variant. Merge variants into intent clusters and keep the calculator workflow first.

## Browser-Control Fallback

If Codex cannot control the logged-in Search Console browser session, export the Performance query table as CSV and run:

```bash
npm run seo:gsc-query-opportunity-import -- --csv <path-to-performance.csv> --start YYYY-MM-DD --end YYYY-MM-DD
```

The importer only reads the provided CSV file. It does not control Search Console, fetch private account data, store cookies, or authorize publication. Generated records stay in `draft` status until a reviewer accepts the query evidence and content decision.

## YMYL Boundary

Queries that ask for personalized amounts, tax bracket limits, state-specific law, IRMAA, ACA, Social Security, NIIT, RMDs, or filing treatment must stay educational unless a reviewed rules engine and source evidence exist.

Recommended wording stays neutral:

- `Based on your inputs`
- `Educational estimate`
- `Review with a qualified tax professional`
- `This calculator does not model every tax interaction`

Avoid:

- direct recommendations,
- optimal conversion amounts,
- guaranteed accuracy claims,
- unsupported external tax or benefit calculations.
