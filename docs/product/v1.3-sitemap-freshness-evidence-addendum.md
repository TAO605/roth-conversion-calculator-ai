# V1.3 Sitemap Freshness Evidence Addendum

Date: 2026-05-30

## Purpose

This addendum makes sitemap freshness auditable for Google Search Console operations. The site already publishes per-page `lastmod` values; this step documents which priority pages require fresh `lastmod` coverage and how the AI agent verifies that coverage before manual URL Inspection or request-indexing work.

## Implemented Scope

- Added a `Sitemap freshness evidence` section to `/seo-monitoring`.
- Added `buildSitemapFreshnessEvidence()` to the SEO monitoring content model.
- Documented freshness-critical URLs and their minimum expected `lastmod`.
- Connected the human playbook to `npm run seo:gsc-evidence`, which parses sitemap entries and reports `lastmodFresh`.

## Freshness-Critical URLs

The current minimum `lastmod` is `2026-05-30` for:

- `/`
- `/seo-monitoring`
- `/methodology`
- `/tax-data-update`
- `/tax-brackets/2026`

These pages are watched because they affect first-screen calculator intent, Search Console operations, methodology/trust disclosure, tax-data operations, and 2026 bracket reference intent.

## Operating Rule

Before retrying Search Console indexing for a priority URL, run:

```bash
npm run seo:gsc-evidence
```

Proceed only when the JSON output shows:

- `status: 200`
- expected `canonical`
- `inSitemap: true`
- `noindex: false`
- `lastmodFresh: true` for freshness-critical URLs

If the command fails on `lastmodFresh`, update the sitemap source metadata and redeploy before touching Search Console.
